# VibeUsage 2049 改版计划

把 dashboard 从 matrix-a 旧风格换成画板 https://claude.ai/artifact/8BFy57cPxYfmrveRhUT6Ut 上定稿的 2049 设计。
受众是打开 Dashboard、Leaderboard、Landing 和各状态屏的用户，以及之后维护 `dashboard/src/ui` 的工程师。
本计划强制一条规则。页面文件只放布局容器和组件引用，样式和重复的原子一律进 `src/ui/shadcn` 或 `src/ui/2049`。
PR 顺序为 P1 升级 Tailwind v4，P2 令牌与 shadcn 初始化，P3 shadcn 组件，P4 2049 基础组件，P5 业务组件，P6 Dashboard，P7 Leaderboard，P8 Landing，P9 删旧。

## How to read this

One box is one unit of work. Every box names the evidence that checks it. A nested box is a sub-step of the box above it. Check a box only when its evidence exists, a file, a log line, a screenshot, a test run, or a SHA. The body is a how-to. The appendices explain and record.

The program runs `pstack/skills/poteto-mode/playbooks/autopilot-full.md`. 每个 PR 的 owner 在拿到 root 的干净结论后自己 squash 合并。P6、P7、P8 改了用户可见的交互，停在 merge-ready，等 operator 看过截图和视频后再合并。

Tests alone are not sufficient verification. A PR is verified only when its unit, live, and perf boxes are all checked.

### PR mechanics, for every PR

- [ ] Resolve the forge once. Default to `gh`; if `command -v origin` succeeds and Origin can resolve the repository, use `origin pr` for every PR operation. Record any fallback to `gh`. Never require `gt`.
- [ ] Open the PR ready, never draft, per **Opening a PR**. Use `gh pr create --base main`. 按仓库的 `.github/PULL_REQUEST_TEMPLATE.md` 填完 Affected Modules、Validation、Risk Flags。
- [ ] Run the repo's lint and typecheck once before the PR-facing push. 命令是 `npm --prefix dashboard run lint` 和 `npm --prefix dashboard run typecheck`。Push with hooks on.
- [ ] Run `/deslop` before each commit and `/no-comments` before review. Claude Code 里没有 cursor-team-kit 的 `/deslop`，改为读 diff 自查注释和冗余代码，并在 PR 里写一行 `Skipped in Claude Code`。
- [ ] Triage every Bugbot and security-reviewer comment per `../references/bugbot-triage.md`. 本仓库对应的是 PR Agent、Macroscope 和 chatgpt-codex-connector 的评论。
- [ ] Rebase onto current trunk before the code-ready report and babysit. Keep that merge base in fix rounds. Rebase again only at merge prep, on a `git merge-tree` conflict with trunk, on a CI failure that comes from a change on trunk, or when a known concurrent change to the same files lands.

### Verdict and merge, for every PR

- [ ] A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head, and a wording-only change gets none. Run each full swarm per `pstack/skills/swarm/SKILL.md`. One gates lane. The ten live lanes from the PR's **Verify, live** block. The perf lane from its **Verify, perf** block. Two or more audit lanes, each with its own focus, that read the diff and the receipts and distrust the PR body. The root audits the receipts in the merge-ready report before the verdict.
- [ ] Judge every finding by the execution playbook's blocking rule. The verdict is clean when none blocks. A failure on trunk behavior in a lane marked `Regression lane against trunk.` is recorded against trunk and does not block the PR. A new head gets a fresh verdict, except for results that stay valid under the patch-id rule in `playbooks/shipping.md`.
- [ ] 合并规则。owner 在 root 给出干净结论、CI 全绿、并且 rebase 后 patch-id 不变时，用 `gh pr merge --squash --delete-branch` 合并。P6、P7、P8 额外等 operator 在对话里放行。代码评审按 operator 的规矩派 `codex:rescue`，只报挡合并的问题。

### Boot recipe, for every live lane

Each live lane runs on its own cloud VM at the PR head. Claude Code 没有云端 VM，每条 lane 用 `isolation: "worktree"` 的独立工作树代替。Drive through `control-ui` or `control-cli` from `cursor-team-kit`. 本机没有 cursor-team-kit，浏览器操作一律用 ego-browser（ego lite）。

- [ ] `git fetch origin <head-branch> && git checkout <head SHA>`.
- [ ] 先跑 `npm ci && npm --prefix dashboard ci`，再用 `VITE_VIBEUSAGE_MOCK=1 npm --prefix dashboard run dev -- --port <5200 加 lane 号>` 起服务，等终端打出 `Local:` 那一行。
- [ ] 只通过 ego-browser 的 `page.goto`、`page.click`、`page.keyboard`、`page.setViewport` 输入。只读诊断用 `page.snapshot` 和控制台日志。主页面地址是 `/?mock=1&screenshot=1`，陈列页地址是 `/__2049?mock=1`。
- [ ] Save every screenshot to `/tmp/swarm-<pr-id>/worker-<n>/<slug>.png` and return the paths with the report.

- 一个大 PR 做完全部。被否决，因为无法逐步验证，回归时也找不到是哪一步引入的。
- 先换页面，再抽组件。被否决，因为违反页面只能用组件拼的规则，抽组件时又得重写一遍页面。
- 留在 Tailwind 3.4，只套 2049 的颜色。被否决，因为 shadcn 的 Base UI 版默认按 v4 生成，留在 v3 要一直靠 `shadcn-retro-fit` 打补丁。
- 用 openspec 写提案。operator 已决定在本仓库弃用 openspec。

## Appendix C. Risks

- P1 有升级后默认值变化的风险。border 默认色、ring 宽度、`shadow-sm` 改名都会改变旧视觉，owner 盯 compare:baselines 的差异比。
- P1 的 `cn()` 有误合并自定义字号和颜色的风险，owner 用 utils 单测守住。
- P2 的 check-design-ssot 会拦 shadcn 默认的 `text-sm` 等类，owner 必须同时改脚本规则，不能绕过。
- P3 到 P5 的新文件会触发 `validate:ui-hardcode` 的新文件规则。owner 让新组件只用 `copy()`、不写字面色值，确实需要时再跑 `--update` 并在 PR 里说明。
- P6 到 P8 会让根目录读源码断言的测试变红，owner 在同一个 PR 里改写它们，只断言组件引用。
- `npm run ci:local` 不跑 dashboard 的 vitest、eslint 和 tsc。每个 PR 的单测框都显式加跑 `npm --prefix dashboard test` 和 `typecheck`。
- 本机没有 cursor-team-kit 的 control-ui，live lane 改用 ego-browser 驱动。ego-browser 的任务空间偶尔会被重置，lane 开头先重新打开页面。
- 会话过期状态没有 URL 开关。P6 的 lane 4 需要 owner 先在 `src/lib/auth-storage.ts` 里查到 localStorage 键名。
- 画板上的 agent 指南链接 `vibeusage.cc/agent-install` 是占位。站点对任意路径都返回 200，路由表里也没有这个路径。P8 改用 copy.csv 已有的 GitHub 指南地址，owner 不要新建这个路径。
